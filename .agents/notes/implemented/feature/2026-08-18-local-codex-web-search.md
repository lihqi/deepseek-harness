# Agent Note: Local Codex-backed Web search

Status: implemented

English | [中文](2026-08-18-local-codex-web-search.zh.md)

## Problem

The shipped `web_search` route used DeepSeek's Anthropic-compatible Messages endpoint and therefore required `DEEPSEEK_API_KEY` independently of the conversation model. A user who already had a working Codex/ChatGPT login still saw search fail when that DeepSeek credential was absent or exhausted. The repository already had a hardened one-shot Codex app-server integration, but it was private to the optional subagent provider and could select only final assistant text; the Web seam could not use it or prove that hosted search had actually run.

## Decision

`@deepseek-ai/dsh-web-search-codex` registers a `WebSearchProvider` as `codex-local`. Each operation creates a temporary root containing an empty workspace and private user-home, temporary, XDG, and Codex state paths; the root uses mode 0700 on POSIX, while Windows uses the platform's directory access controls. The provider resolves the created root through `realpath` before deriving child paths; on macOS this keeps exact path comparisons aligned with app-server's canonical temporary paths. `env.CODEX_HOME`, ambient `CODEX_HOME`, or the platform default selects an absolute source home in that order; the provider accepts only its regular `auth.json`, bridges that file into the private Codex home with a canonical absolute file symlink or a Windows same-volume hard-link fallback, and fails before spawn when source validation or setup fails. Codex uses its file credential store, so native token refresh writes through the bridge and updates the selected source `auth.json`. It then starts the package-fixed Codex 0.149.1 payload as `codex app-server --stdio --strict-config` through `ctx.subprocess`. The `model` config requires a non-whitespace value, trims it for dispatch, and defaults to `gpt-5.5`; under this fixed payload, `gpt-5.6-sol` uses Responses Lite and does not expose the hosted Responses `web_search` tool. Launch configuration disables apps, plugins, bundled skills, and every known 0.149.1 non-search feature or tool while retaining built-in hosted search.

The shared Codex wire exposes a bounded `./app-server` export rather than a generic JSON-RPC escape hatch. Its handshake, thread/turn association, unattended approval denial, cancellation, final-answer selection, and whole-tree disposal remain the single implementation. The bounded export covers experimental initialization options, effective configuration and requirement reads, skills and MCP-server status, empty-environment and instruction-source assertions, optional thread/turn policy fields, and completed `webSearch` observations. Codex 0.149.1 cannot exclude system or cloud managed configuration before startup, so that state may enter the process; before any user query is sent, the provider inspects `config/read`, `configRequirements/read`, `skills/list`, and `mcpServerStatus/list` and fails if effective external configuration, requirements, skills, or MCP servers remain. Process config and thread config both set `orchestrator.mcp.enabled=false` and `orchestrator.skills.enabled=false`. The search thread additionally requires `environments: []`, empty `instructionSources`, the empty workspace, `project_doc_max_bytes: 0`, `approvalPolicy: never`, and a read-only sandbox. The subagent's option-free calls preserve their existing request behavior.

Search supplies Codex with developer instructions that treat the query as untrusted research data, forbid command/file work, require built-in Web search, and require only schema-constrained JSON. A success must carry both at least one authoritative completed `webSearch` item and a parseable `{ content, sources[] }` final message. The item proves that hosted search ran during the turn; Codex 0.149.1 does not expose a reliable relation between that item and every final source URL, so the provider does not claim per-citation provenance. Sources must use HTTP(S), optional fields retain only non-empty strings, duplicate URLs collapse first-wins, and `maxResults` becomes JSON Schema `maxItems` before the provider-neutral seam enforces it again. The provider never extracts URLs from prose and rejects a turn with no hosted-search activity.

Before process dispatch, the initiating session records `web/codex-search-llm-request` with the intended `developerInstructions`, `model`, `searchMode`, `prompt`, and `outputSchema`. These fields reconstruct every model-visible input owned by the provider. The event contains no provider credential but persists the original query inside `prompt`, so user-supplied sensitive text remains in the session log. It records the attempt; it does not prove that a process or turn started or that the query reached Codex. `env.CODEX_HOME` only selects the authentication source; the provider removes every ambient child-environment entry, replaces `HOME`, `USERPROFILE`, `TMPDIR`, `TMP`, `TEMP`, the XDG paths, `CODEX_HOME`, and `CODEX_SQLITE_HOME` with paths inside the private root, and forwards only explicitly configured `OPENAI_BASE_URL`, `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, and `NO_PROXY`. Loader and path-control fields are rejected. `OPENAI_BASE_URL` must use HTTPS except for loopback HTTP and receives the native authentication plus query; explicitly configured proxies can observe or modify that traffic, so both settings are deployment trust decisions. No other source-home file is linked or copied into that root.

The base bundle selects `searchProvider: codex-local`, mounts `web-search-codex` with `searchMode: live`, gives each complete `web_search` invocation a shared 120-second `dsh-tool-web` budget across all queries and authentication-queue waiting, and keeps the provider-neutral base setting `fetch: false`. It also mounts the hardened `web-fetch-http` provider; the shipped Web `cordis`, `ptc`, and `standard` presets override `fetch: true`, so changing the search provider preserves their existing safe fetch capability. The bundle includes `dsh-subagent-codex` only because that package owns the public app-server adapter; it does not mount the `codex` subagent provider or expose a subagent tool. This note owns the provider choice and its authentication, tool, process, and timeout realization; [Default Web search in shipped compositions](2026-07-31-web-default-search.md) continues to own the shared-base placement and fetch defaults.

## Alternatives considered

**Call the OpenAI Responses API directly with a ChatGPT token.** Rejected because Codex authentication is product-owned and not an API key contract DSH should read, copy, refresh, or emulate. The official app-server is the supported integration boundary and already owns login resolution.

**Execute `codex exec --json`.** Rejected because structured output would require a temporary schema file, event association and approval handling would be inferred from a CLI presentation stream, and process cancellation would duplicate the app-server implementation already in the repository.

**Put Codex mode inside `web-search-deepseek`.** Rejected because provider packages name their actual backend. One configuration surface switching between unrelated authentication, protocol, and failure contracts would make both implementations shallower and harder to test.

**Accept any structured final answer without hosted-search activity.** Rejected because output schema proves response fields, not whether hosted search ran. Requiring a completed `webSearch` item establishes turn-level search activity, but does not establish that every final URL came from that search.

**Keep DeepSeek search as the shipped default and make Codex opt-in.** Rejected for this deployment goal: the user's already authenticated local Codex entitlement is the intended search credential. DeepSeek, Exa, and Perplexity providers remain available for custom overlays.

## Consequences

Default DSH search authenticates through the local user's Codex entitlement and does not require `DEEPSEEK_API_KEY`. It fails at operation time when the authentication file is unavailable, login has expired, hosted search is unavailable, quota is exhausted, or pre-query inspection finds external configuration, requirements, skills, or MCP servers. Loading the plugin performs no process or network probe, which keeps startup deterministic but means synchronous provider availability cannot predict account state.

Each search pays for a complete isolated Codex turn and one process lifecycle. A `globalThis` coordinator keyed with `Symbol.for` serializes every provider instance in the Host process and survives source HMR because Codex 0.149.1 has no cross-process refresh lock; a queued cancellation releases its FIFO position without resolving operation options or spawning. This prevents one DSH Host from racing its own refresh writes, while unrelated Codex processes remain outside that ownership. A real-product Responses sentinel pins hosted `web_search` as the only outbound tool for the default model under Codex 0.149.1 and proves that an ambient Node preload cannot run. The result returned to the conversation contains a Codex-generated summary plus normalized sources whose individual provenance is not established by the 0.149.1 app-server events. Teardown closes the wire, terminates the complete process tree, and removes the temporary root only after exit is proven; an unproven exit retains the root and live authentication bridge, poisons Codex search process-wide, and becomes a cleanup failure. Every provider instance stays unavailable through source HMR until Host restart; `available()` reports false, and queued cancellation remains `WEB_ABORTED` even when its predecessor poisons the process coordinator. The provider-neutral base remains search-only, while the shipped Web presets retain model-selected URL fetching through the hardened `web-fetch-http` provider; Codex search neither grants nor removes fetch by itself.

The provider protocol tests use an in-memory JSON-RPC app-server boundary and pin authentication preflight, POSIX symlink and Windows hard-link bridges, canonical path isolation, model normalization and logging, process-and-thread orchestrator shutdown, strict launch configuration, external-state rejection before query dispatch, empty thread environments and instruction sources, structured mapping, strict no-search rejection, malformed-result rejection, queued cancellation, cross-instance and HMR-stable serialization, source poisoning, cancellation with cleanup aggregation, process-tree quiescence, HMR disposal, and invariant ownership. A real-product test pins the default model's 0.149.1 Responses tool set. Existing subagent tests pin option-free behavior. The package README records the user-facing configuration and Model Experience, while generated catalogs and module graphs include the new provider.
